This site explains how to operate, understand, consume, and safely automate the accounting system. It does not own ledger data, accounting calculations, source documents, viewer implementation, live runtime truth, or production scheduler deployment state.

## Current backend spine

```text
canonical ledger ingest
  -> governed materialization / semantic + cash facts
  -> debt position/activity + treasury
  -> governed monthly frontier + annual dashboard
  -> publication bundle
  -> professional presentation + governed drilldowns
```

The current executable backend does **not** use a generic views stage, a parallel `metric_values` engine, or `accounting.human.*` as accounting authority. Older pages may still mention those concepts during the staged documentation migration; those references are not controlling current architecture.

## Repository boundaries

- `accounting-workflows`: canonical transformations, accounting rules, governed reporting calculations, publication generation, professional packs, drilldowns, and executable command behavior.
- `accounting-viewer`: viewer-specific read-only presentation over packaged outputs. Its current loader still reflects an older package-path convention, so viewer availability is not proof of current governed-bundle freshness.
- `accounting-docs`: public operating, architecture, contract, consumer, and automation-policy guidance.

Accounting classifications documented here do not determine legal ownership, rights, enforceability, family governance, or negotiation positions. Scheduling policy likewise does not create accounting or legal meaning.
